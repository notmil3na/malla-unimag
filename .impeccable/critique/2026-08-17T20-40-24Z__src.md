## Design Specificity Verdict

MiMalla avoids the generic "student dashboard" trap with university-specific taxonomy (cortes, semestres, prerequisitos), the "Atlas Aurora" design system (nebula backgrounds, gold accent, glass surfaces), and a genuinely sophisticated schedule planner. However, the visual execution doesn't fully capitalize on this specificity. Every view follows the same structural pattern (header → summary → list of cards → save button), which creates consistency but also sameness that flattens hierarchy across fundamentally different tasks. The detector found 11 "side-tab" thick left-border patterns across 6 components — the most recognizable AI-slop pattern — plus 343 font-size deviations suggesting the DESIGN.md type ramp doesn't match reality.

## Priority Issues

### P0 — Data Loss Risk: Cascading Malla Changes
**File:** MallaView.jsx:108-148
Changing one materia silently flips 5+ dependent materias with no undo. Toast fires but user cannot reverse.
**Fix:** Preview modal or 5-second undo window.

### P1 — Inconsistent Save Semantics
**Files:** HorarioView.jsx:1026 (auto) vs NotasView.jsx:298 (manual) vs CursandoView.jsx:426 (manual)
Users cannot build a mental model of when data is safe.
**Fix:** Standardize on auto-save or explicit save with visible indicator.

### P2 — Touch Targets Below 44px (WCAG 2.5.5)
**Files:** Sidebar.jsx — .modeToggle 34x34, .profileLogout 30x30
High-traffic sidebar buttons undersized for mobile.
**Fix:** Increase to 44x44px minimum.

### P2 — Missing ARIA Labels on Login
**File:** Login.jsx — 10 inputs, 2 selects with placeholder-only, no htmlFor linkage
Entry point for every user fails WCAG 1.3.1 and 4.1.2.
**Fix:** Add aria-label or htmlFor on all form controls.

### P2 — Empty State Gap in Dashboard
**Files:** Dashboard.jsx:99, HorarioView.jsx:998-1000
Default tab is empty horario for new users. No onboarding CTA.
**Fix:** Show guided flow when zero classes exist.
